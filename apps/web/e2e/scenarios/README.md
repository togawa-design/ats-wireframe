# シナリオテスト

機能単体のハッピーパス（`e2e/*.spec.ts`）とは別に、複数機能をまたぐ業務フロー
（例: 応募者登録→選考ステージ進行→内定→LINE通知）を検証するテストをここに置く。

## いつ書くか

機能を1つ作るたびには書かない（`TESTING.md` の「完了の定義」には含まれない）。
関連する一連の機能が揃ったタイミングで、そのフロー全体を通しで検証するテストを
1本追加する。書きすぎるとステップ数が多く壊れやすいテストが増えるため、
本当に重要な業務フローに絞る。

## 書き方

`e2e/*.spec.ts` と同じ Playwright の仕組みをそのまま使う
（`playwright.config.ts` の `testMatch` が `e2e/scenarios/**/*.spec.ts` も拾う）。
認証・DBのセットアップは `e2e/global-setup.ts` を共用する。
